# MFS MIND-MAP REVEAL ANIMATION ENGINE
## Cinematic Metals × Quiet Intelligence
### Hierarchical Flow Reveals for All Ten Automation Services

Build a sophisticated, interactive, mind-map-style animation system for the Murali Forge Systems website.

The animation must behave like a dynamically revealed concept map: a central concept appears, connecting lines draw outward, major branches emerge, sub-branches reveal progressively, and the entire workflow becomes visible as a connected system.

This is NOT a dashboard animation, a vertical timeline, a slideshow of screens, a collection of cards, or a sequence of interface mockups.

The primary visual object is the **expanding, connected mind map itself**.

Use copper for primary paths and active branches. Use steel blue for secondary branches. Use champagne to highlight the currently revealed node or active path.

## 2. REQUIRED REVEAL SEQUENCE

Every service demo must use this animation model.

### Phase A — Central node

Display only the central topic.

Animate it into view through a refined opacity and scale transition. Add a restrained copper edge highlight.

Example:
`Lead Capture & CRM Automation`

### Phase B — Primary branches

Draw curved or smoothly routed SVG connector paths from the central node to the first-level branches.

A connector must begin at the parent node and visibly draw toward its child.

Reveal the child node when the connecting line reaches its destination.

Do not reveal all branches simultaneously.

### Phase C — Sub-branches

Reveal the next level of the hierarchy one branch at a time.

For each branch:
1. Draw its connector.
2. Illuminate a subtle travelling signal along the path.
3. Reveal the destination node.
4. Reveal its label.
5. Continue into its children.

Allow the animation to pause briefly between meaningful groups so the structure can be understood.

### Phase D — Conditional branches

When a workflow has different possible outcomes, reveal the decision node and then the relevant branches.

Examples:
- Valid versus invalid data.
- Available versus unavailable appointment.
- Standard versus urgent support.
- Successful processing versus an exception.

In interactive mode, the user must be able to select a scenario and reveal the corresponding branch.

Do not present mutually exclusive results as though all occurred in the same execution.

### Phase E — Complete map

Once the selected flow has finished, show the full connected map.

Provide a clear final state, such as:
`Workflow completed`
or
`Human review required`.

Keep the complete map visible for exploration.

## 3. CAMERA AND SPATIAL MOVEMENT

Treat the mind map as a large visual canvas.

As new branches appear, gently pan or zoom to maintain the active branch in a comfortable viewing area.

Use smooth camera interpolation. Never jump abruptly between branches.

Preserve the relationship between the parent and child nodes while the camera moves.

The complete map should remain navigable after the reveal finishes.

Include:
- Replay animation.
- Reset map.
- Fit entire map to viewport.
- Zoom in and zoom out.
- Pan by dragging.
- Click or tap a node to select it.
- Keyboard-accessible node navigation.
- A way to pause or step through the reveal when appropriate.

Avoid zooming so far that labels become unreadable.

Use a full-map view at the end of the reveal.

On mobile, adapt the map to a smaller viewport with appropriate zoom, panning, and node selection.

## 4. NODE DESIGN

Create three visual levels.

**Root node:** The central service or workflow.

Use the strongest visual emphasis, a refined metallic border, and a soft copper highlight.

**Primary branches:** Main workflow phases or functional areas.

Use medium-sized nodes and copper or steel-blue connectors.

**Leaf nodes:** Specific actions, data, rules, or outputs.

Use smaller, low-contrast nodes with readable labels.

Selected nodes should receive a clear active state.

Completed nodes should retain a subtle completed indicator. Error or exception branches must have explicit text labels instead of relying solely on color.

Avoid making every node a separate large card. The connectors and spatial relationships are the main visual language.

## 5. MOTION DETAILS

Use SVG-based connector drawing or an equivalent geometry-aware technique.

Animate actual connector paths, not decorative lines placed independently beside the nodes.

Use:
- Path drawing with stroke-dasharray and stroke-dashoffset, or an equivalent approach.
- Restrained node scale and opacity transitions.
- Subtle signals travelling along active connections.
- Controlled active-node highlighting.
- Branch-by-branch stagger.
- Smooth camera movement.
- Small changes in material highlight.
- A clear visual distinction between active, completed, and conditional paths.

The movement must communicate hierarchy and progression.

Do not use excessive bounce, chaotic particle effects, flashing, spinning cards, or random movement.

## 6. INTERACTION AND DATA BEHAVIOR

Represent each workflow as structured data containing nodes, connections, hierarchy, optional conditions, and output details.

The animation engine must reveal this structure progressively.

User input and scenario selection must influence which nodes, values, and branches are displayed.

The visual map must never contradict the underlying simulation.

After completion, selecting a node should display its concise explanation, inputs, outputs, and status in a small contextual detail area.

Do not obscure the map with large panels.

All ten demos must have their own correct workflow structure, while sharing the same map-rendering and animation engine.

## 7. ACCESSIBILITY AND PERFORMANCE

Implement keyboard navigation, focus states, accessible node labels, reduced-motion behavior, and responsive sizing.

Provide a nonanimated way to inspect the complete workflow.

Clean up animation frames, event listeners, and observers.

Avoid excessive DOM nodes and unnecessary full-page re-rendering.

Use a suitable implementation based on the actual project. Prefer React with SVG when the project uses React and SVG meets the requirements. Use a graph or canvas library only if justified.

Preserve the existing website architecture and change only the files necessary to implement this system.

# 9. DEFINITION OF DONE

A demo is complete when:
- The central node appears first.
- Its primary connecting paths visibly draw.
- Branch nodes reveal progressively.
- Sub-branches unfold in a meaningful order.
- Camera movement follows the reveal without abrupt jumps.
- The final connected map is visible.
- Selecting nodes works.
- Conditional branches reflect actual simulation state.
- Reset and replay work.
- The map remains understandable without animation.
- All labels and outputs match the actual workflow data.

Implement these ten maps inside the existing MFS website. Do not modify unrelated projects, invent additional services, or replace the map animations with cards or static illustrations.

Verify the real browser behavior before declaring the work complete.
